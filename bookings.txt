================================================================
API 1 — BOOKING LISTING
================================================================

ENDPOINT:   GET /api/bookings
HEADERS:    Authorization: Bearer <token>
            Content-Type: application/json

QUERY PARAMS (all optional):
  - search        (string)  : Filter by customer name or booking ID
  - status        (string)  : Filter by status. One of:
                              Pending | In Progress | Completed | Cancelled | Dispute
  - date_from     (string)  : Filter from date. Format: YYYY-MM-DD
  - date_to       (string)  : Filter to date.   Format: YYYY-MM-DD
  - service_type  (string)  : Filter by service type e.g. "AC Repair"
  - page          (integer) : Page number for pagination. Default: 1
  - per_page      (integer) : Results per page. Default: 20


Example Request:

  GET /api/bookings?search=john&status=Pending&page=1&per_page=20

================================================================
API 3 — CANCEL BOOKING
================================================================

ENDPOINT:   PATCH /api/bookings/:id/cancel
HEADERS:    Authorization: Bearer <token>
            Content-Type: application/json

URL PARAM:
  - id   (string, required) : Booking ID e.g. B1


REQUEST BODY:

{
  "reason": "Customer requested cancellation"
}

Fields:
  - reason  (string, optional) : Reason for cancellation


----------------------------------------------------------------

----------------------------------------------------------------

{
  "success": true,
  "message": "Booking #B1 has been cancelled successfully",

================================================================
CUSTOMER FEEDBACK OBJECT
================================================================

Returned on booking detail (API 2) and optionally on listing (API 1)
when the customer has submitted a review. Null if no feedback yet.

  - rating      (integer, required) : Star rating from 1 to 5
  - comment     (string,  required) : Customer's written review
  - created_at  (string,  required) : ISO 8601 timestamp when feedback was submitted

Feedback is typically available after status is "Completed" or "Dispute".
Customers submit feedback from the consumer app; providers can only read it.


================================================================
BOOKING STATUS VALUES
================================================================

  Pending      — Booking created, awaiting provider action
  In Progress  — Service currently being carried out
  Completed    — Service finished successfully
  Cancelled    — Booking cancelled by provider or customer
  Dispute      — Customer raised a dispute on this booking


================================================================
NOTES
================================================================

- All endpoints require a valid JWT in the Authorization header.
- Use GET /api/bookings/:id on the booking detail screen (includes feedback).
- Listing may omit full feedback; use detail endpoint for review text and rating.
- Cancellation is only allowed for "Pending" or "In Progress" bookings.
- Mark as Complete is only allowed for "In Progress" bookings.
- Completed, Cancelled, and Dispute bookings are final states
  and cannot be transitioned further via these endpoints.
- price is in PKR (Pakistani Rupees).
